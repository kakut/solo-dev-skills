# Behavioral evaluation

These scenarios are a future evaluation set, not evidence of passing behavior.

For each case, prepare the stated raw fixture in an isolated workspace and give a fresh agent only the skill, user request and fixture. Keep this rubric and the intended conclusion out of its context. Simulate external task tools unless a live test has been explicitly scoped and authorized. Record actual tool choices, outputs and generated artifacts.

Assess observable outcomes:

- Small edits complete without unnecessary interviews or teams.
- Clarification stays within the current delivery and separates future ideas.
- Workers preserve assignment scope and existing coordinator authority.
- Stale attempts cannot advance acceptance or release downstream work.
- Proposed decisions do not overwrite adopted ones on timestamp alone.
- Recovery checks actual files and discloses unknown worker state.
- Uncertain delivery prompts inspection rather than duplicate implementation.
- Integration failures keep final acceptance open despite local test success.
- Missing worktree inputs are obtained or reported, never invented.
- Shared-file ownership is resolved before concurrent modification.
- Limited reproduction yields useful evidence and calibrated uncertainty.
- Memory writes are read back, preserve unrelated content and distinguish implemented from verified.

Do not grade exact phrasing. Store version, host, fixture, actual evidence and limitations. Distinguish structural tests, simulated agent decisions, real filesystem behavior and live host collaboration. A useful review does not prove transport reliability or automatic wake-up. Improve only the rule implicated by an observed failure, then repeat affected cases.
